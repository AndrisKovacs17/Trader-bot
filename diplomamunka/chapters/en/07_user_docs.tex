\chapter{Software System Overview}
\label{ch:user_docs}

\section{System Architecture}

As an experimental infrastructure for KCMamba research, a complete
production-ready trading system was developed with three main components:
an asynchronous trading engine in a hexagonal architecture,
a backtesting framework on historical data,
and a Binance adapter for live market data and order execution.

The engine follows a ports-and-adapters (hexagonal) pattern~\cite{cockburn2005hexagonal},
ensuring that the \texttt{core} business logic runs unchanged with both test
and live adapters. The KCMamba model is hot-swappable via the \texttt{ModelStore}
interface.

\section{Requirements and Installation}

Python~3.10+ is required; GPU is optional (CPU execution is supported).

\begin{verbatim}
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env   # Fill in BINANCE_API_KEY and BINANCE_SECRET for live mode
\end{verbatim}

\section{Running the System}

\subsubsection*{Paper-trading demo (default)}

\begin{verbatim}
python main.py
\end{verbatim}

The system receives live Binance WebSocket data, runs KCMamba inference,
generates ThresholdStrategy signals, but sends \emph{no} real orders.

\subsubsection*{Backtesting}

\begin{verbatim}
python -m adapters.testing.backtest --symbol BTCUSDT --start 2024-01-01 --end 2024-06-01
\end{verbatim}

Runs without a Binance connection; writes results to console and CSV.

\subsubsection*{Offline benchmark (experimental evaluation)}

\begin{verbatim}
python tdk_sweep.py --resume    # Reproduces all results in Chapter~\ref{ch:kiserletek}
\end{verbatim}

\section{Security Considerations}

The demo runs in paper-trading mode by default and sends no real orders.
When using a live API key, (a)~grant only Futures trading permissions on
the Binance side, and (b)~apply an IP whitelist. The dashboard listens on
\texttt{localhost:8080} by default; exposing it on a public IP requires
a reverse proxy (e.g.\ nginx).
